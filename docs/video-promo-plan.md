# 宣传片分镜计划（From CLI to Clarity）

这份文档是**实现用**的分镜表：每一拍多长、画什么、数字从哪来。给 AI 视频工具的提示词在
`docs/video-ai-prompt.md` 和 `docs/video-15s-segments.md`，录屏方案在 README 的 `yarn video`。

渲染方式：`yarn promo`（见 README 的 `promo` 一节）。当前进度：**第 ② 拍已完成**，尺寸 1920×1080 /
1080×1920，30fps，H.264。

---

## 一、先说数据：分镜里的数字不能编

你给我的那版分镜写得很顺，但里面的数字和界面**基本都不是这个产品真实的样子**。这不是文风问题：
开发者会照着视频去数，对不上就是虚假宣传，比画面粗糙严重得多。

| 分镜里写的 | 实际是 | 性质 |
| --- | --- | --- |
| `47 Findings` | **389** | 数字编的 |
| `Critical 2 / High 8 / Medium 21 / Low 16` | **2 / 34 / 179 / 174** | 数字编的，而且总量对不上 |
| `382 files → 12 files` | 机制真实（分批收敛），但 382 和 12 是编的 | 机制真、数字假 |
| `5 files / 12,438 lines`、`+382 −124` | 预览面板其实是**文件 / 状态 / 说明**三列表格，没有行数统计，也没有增删行数 | 界面画错了 |
| `72%` 环形进度、`Analyzing → Understanding → Reviewing → Complete` | **产品里不存在**。真实状态文案只有 `正在启动…` / `正在收集结果…` / `已完成` / `已中断` / `失败`，配一个已用时间 | 功能是编的 |
| ASCII 的 OcrLens 方框 | 真实界面是吸顶筛选条 + 按文件分组的卡片网格 | 界面画错了 |

真实数据来自 `~/.opencodereview/sessions/<repo>/<id>.jsonl`（38.3 MB），统计口径是
`review_item_done.comments[]`：**389 条 finding，跨 115 个文件**；严重度 `high 34 / medium 179 /
low 174 / critical 2`；类别 `bug 206 / maintainability 131 / documentation 22 / performance 16 /
security 7 / style 7`；单文件最多 13 条。

所以这一版分镜的原则是：

1. **数字只用真的**，宁可少讲。拿不到真实数字的环节就不要出现数字。
2. **界面不手绘**。要展示界面就用 `yarn video` 真录，或者用真实 DOM 渲染；不要用 AI 生成 UI 图。
3. **不发明产品没有的状态**。用上面那五个真实文案。
4. 演示仓库用**专门建的匿名仓库**（`my-project`，里面种一个 `localStorage` 存 token 的问题），
   绝不用真实私有项目 `Pixelizer`——录屏和成片里都不能出现这个项目名、路径或真实会话标题。

## 二、分镜表

标题 From CLI to Clarity，总长约 42s。✅ = 已实现，⬜ = 待做。

| # | 时长 | 内容 | 真实数据 | 状态 |

| ① | 4s | 终端里一条命令跑起来，`ocr review --repo my-project` | — | ⬜ |

| ⑥ | 4s | 严重度 / 类别筛选条被点击，卡片收拢 | 真实分布 | ⬜ |

| ⑧ | 4s | 重新跑一次同一仓库，finding 数下降 | 需真实二次运行数据 | ⬜ |

第 ② 拍之所以先做，是因为它**不需要演示仓库**，只出现 `finding` 这个词和数字 `389`，却能把
「信息太多 → 收敛成一个数」这个核心叙事走完，同时把渲染管线、双画幅、观感全部验证掉。风格定了
再铺剩下 37s。

### 第 ② 拍的时间轴（30fps，150 帧 = 5.000s）

| 帧 | 画面 |
| --- | --- |
| 0–45 | 终端窗口里逐行刷出 `finding`，0.42 帧一行，边打印边往下溢出窗体 |
| 45–90 | 96 个字按黄金角散布方向飞出去，逐个错开起跳，边飞边旋转 |
| 48–66 | 终端窗体自身淡出，字段接管画面 |
| 69–90 | 所有字回收进画面中心，同步缩小并淡出 |
| 90–120 | `389` 从中心爆出，`easeOutBack` 带一点过冲 |
| 108–126 | 下方 `FINDINGS` 逐字拉开字距淡入 |
| 126–150 | 定格，中心绿色辉光轻微加深 |

数字 `389` 是这次真实统计的结果，不是凑的。
